# Для разработчика

## Запуск без Docker

Нужны Python 3.12+, Node 22+, PostgreSQL 16 (с `pg_dump` и `pg_restore` в PATH).

```bash
# база
createdb erp
# сервер
cd backend
pip install -r requirements.txt -r requirements-dev.txt
export DATABASE_URL=postgresql+psycopg://postgres@127.0.0.1:5432/erp ADMIN_LOGIN=admin ADMIN_PASSWORD='надёжный-пароль' COOKIE_SECURE=false BACKUP_DIR=./backups
alembic upgrade head
python -m app.cli seed-demo --yes      # по желанию: вымышленные данные
uvicorn app.main:app --port 8000
# сайт (в другом окне)
cd frontend
npm ci
npm run dev                             # http://localhost:5173, запросы /api уходят на порт 8000
```

Либо вместо `DATABASE_URL` задайте `POSTGRES_HOST`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_PORT` (так делает Docker; спецсимволы в пароле безопасны). Для копий нужен `PG_BIN_DIR`, если `pg_dump` не в PATH.

## Тесты

```bash
cd backend
TEST_ADMIN_URL=postgresql+psycopg://postgres@127.0.0.1:5432/postgres python -m pytest tests -q
```

Тесты создают и удаляют свою базу `erp_test`; нужен пользователь с правом `CREATEDB`. Сейчас 397 тестов. Часть из них запускает настоящие `pg_dump` и `pg_restore`.

Сайт: `npx tsc --noEmit` (проверка типов) и `npm run build`.

## Команды сервера

`python -m app.cli init` — справочники и роли; `create-admin` — первый администратор; `seed-demo --yes` — демо-данные; `backup` — копия сейчас; `verify ID` — проверка копии восстановлением.

## Устройство

- **Права**: коды в `app/permissions.py`; на каждый запрос вычисляется, в каких юрлицах действует каждое право (`Scope`). Суффикс `_own` — «только своё».
- **Вход**: непрозрачные сеансы на сервере (cookie `erp_session`, HttpOnly, SameSite=Lax), в базе только sha256 токена; защита от подделки запросов через заголовок `X-CSRF-Token`.
- **Защита данных в самой базе** (миграция `0001_initial.py`): триггеры запрещают менять и удалять журнал действий, события обращений, историю статусов, исправления листов; `guard_readings` запрещает менять показания. Частичные уникальные индексы: один открытый лист на машину.
- **Ошибки** возвращаются как `{code, message, field}`; ошибки проверки полей — `{code: "validation", fields}`.
- **Время** хранится в UTC, показывается по часовому поясу организации (`ORG_TIMEZONE`).
- **Нумерация** листов и обращений — атомарная (`INSERT … ON CONFLICT … RETURNING`), своя для каждого юрлица.

- **Учётные разделы** (справочники и деньги: контрагенты, тарифы, константы, топливные карты, штрафы, аренда, расходы, выплаты, счета, касса): каждый описан один раз в `app/resources.py` (поля, подписи, правила), а общий каркас `app/registry.py` даёт для него список с поиском, отбором по датам и состоянию, итоги, выгрузку в CSV, добавление, правку, архив с причиной, возврат из архива, права `<раздел>.view/create/edit/void`, запись в журнал и проверку связей (техника, сотрудник и счёт должны быть из того же юрлица). Экран один для всех (`frontend/src/pages/Registry.tsx`) и строится по описанию с сервера (`/api/<раздел>/meta`). Новый такой раздел = модель + миграция + права + запись в `resources.py` + строка в `frontend/src/sections.ts`. Тесты: `tests/test_registry.py`.
- **Деньги**: суммы хранятся как `Numeric(14,2)`, принимаются только обычные числа (запятая или точка, пробелы допустимы; «1e3», «inf» и т. п. отклоняются), округление до копеек. Записи не удаляются, а уходят в архив.
- **Сводка и кабинет водителя**: `app/routers/roster.py` (`GET /api/roster`, выгрузка `/api/roster/export.csv`; блоки наряда, рейса, заправки и обращений приходят только если есть право на них) и `app/routers/driver.py` (`GET /api/driver/home`, нужно право `vehicles.view_own`). Главная водителя в `frontend/src/pages/DriverHome.tsx` включается по правам: есть `vehicles.view_own` и нет `vehicles.view`.
- **Работа без связи**: очередь записей в IndexedDB (`frontend/src/outbox.ts`, хранилище `erp-outbox`; записи рейса и заправки, отметки наряда и фото; отправляются по порядку; при ответе сети 5xx или обрыве очередь останавливается и ждёт, при отказе 4xx запись остаётся с причиной), уменьшение фото (`images.ts`), служебный скрипт `frontend/sw-template.js` (в `dist/sw.js` его кладёт плагин в `vite.config.ts`; сохраняет оболочку программы и данные только четырёх запросов водителя; ответы 401 и 403 из сохранённого не подменяются) и `offline.ts` (регистрация, стирание сохранённого при выходе и смене человека). Отметки наряда принимают `at` (время нажатия на телефоне): сервер верит ему только в разумных пределах (не раньше чем за 3 дня и не позже чем на 5 минут вперёд), иначе ставит своё время. Проверить служебный скрипт локально: `npm run build && npx vite preview` (порт 4173, `/api` проксируется на 8000).
- **Детали, «Что купить», счета на ремонт** (этап 2в): `app/services/parts.py` (проверка строк, каталог названий `parts_catalog` с подсказками, подсказка «уже меняли» по истории машины и показаниям, автоматический сдвиг статуса обращения только от покупки), `app/routers/request_parts.py` (детали обращения и `/api/part-options`), `app/routers/purchases.py` («Что купить»: свёртка одинаковых деталей, отметка, возврат, CSV), `app/services/bills.py` и `app/routers/bills.py` (счета: суммы и НДС «в том числе» по строкам с округлением ROUND_HALF_UP, нумерация через `services/numbering`, файлы в базе, чтение PDF через `pypdf` без сохранения, архив с причиной, сводка, печатные данные `/api/print/bills/{id}`). Каталог деталей — обычный учётный раздел `parts` в `resources.py`. Список поставщиков для счёта: `/api/options/supplier` (доступен и тому, кто вносит счета). Миграция `0007` (каталог заполняется 54 типовыми деталями). Экраны: `pages/Purchases.tsx`, `pages/Bills.tsx`, `pages/BillForm.tsx`, `pages/BillCard.tsx`, `components/PartsEditor.tsx`, `components/RequestParts.tsx`, печать `repair_bill` в `pages/Print.tsx`. Тесты: `test_parts.py`, `test_purchases.py`, `test_bills.py`.
- **Табель и СИЗ** (этап 3а): `app/services/timesheet.py` (разбор клетки, итоги), `app/routers/timesheet.py` (`GET /api/timesheet`, `PUT /api/timesheet/cells`, `POST /api/timesheet/fill`, `export.csv`), `app/services/ppe.py` и `app/routers/ppe.py` (состояние и замена), нормы и выдача в `resources.py`; миграция `0008`; сайт: `pages/Timesheet.tsx`, `pages/TimesheetPrint.tsx`, `pages/ppeActions.tsx`, `components/EmployeePpe.tsx`.
- **События сотрудников, календарь и напоминания** (этап 3б): `app/services/reminders.py` (один сборщик сроков из разделов с проверкой прав и юрлиц, нужен и календарю, и напоминаниям), `app/routers/calendar_view.py` (`GET /api/calendar?view=month|week|day|year`), `app/routers/reminders.py` (`GET /api/reminders`, `/summary`, `/export.csv`), разделы `employee_events` и `calendar_events` в `resources.py`; миграция `0009`; сайт: `pages/Calendar.tsx`, `pages/Reminders.tsx`, `components/EmployeeEvents.tsx`, карточка на главной и значок в меню; тесты `tests/test_events_calendar.py`.
