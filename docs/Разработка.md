# Для разработчика

## Запуск без Docker

Нужны Python 3.12+, Node 22+, PostgreSQL 16 (с `pg_dump` и `pg_restore` в PATH).

```bash
# база
createdb erp
# сервер
cd backend
pip install -r requirements.txt -r requirements-dev.txt
export DATABASE_URL=postgresql+psycopg://postgres@127.0.0.1:5432/erp ADMIN_LOGIN=admin ADMIN_PASSWORD='надёжный-пароль' COOKIE_SECURE=false BACKUP_DIR=./backups
alembic upgrade head
python -m app.cli seed-demo --yes      # по желанию: вымышленные данные
uvicorn app.main:app --port 8000
# сайт (в другом окне)
cd frontend
npm ci
npm run dev                             # http://localhost:5173, запросы /api уходят на порт 8000
```

Либо вместо `DATABASE_URL` задайте `POSTGRES_HOST`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_PORT` (так делает Docker; спецсимволы в пароле безопасны). Для копий нужен `PG_BIN_DIR`, если `pg_dump` не в PATH.

## Тесты

```bash
cd backend
TEST_ADMIN_URL=postgresql+psycopg://postgres@127.0.0.1:5432/postgres python -m pytest tests -q
```

Тесты создают и удаляют свою базу `erp_test`; нужен пользователь с правом `CREATEDB`. Сейчас 751 тест. Часть из них запускает настоящие `pg_dump` и `pg_restore`.

Сайт: `npx tsc --noEmit` (проверка типов) и `npm run build`.

## Команды сервера

`python -m app.cli init` — справочники и роли; `create-admin` — первый администратор; `seed-demo --yes` — демо-данные; `backup` — копия сейчас; `verify ID` — проверка копии восстановлением; `import-old --db ФАЙЛ [--apply] [--default-entity НАЗВАНИЕ] [--report ФАЙЛ]` — перенос данных из старой программы (без `--apply` пробный запуск); `decrypt-backup --in ФАЙЛ.enc --out ФАЙЛ.dump` — расшифровать копию, пришедшую вне сервера.

## Устройство

- **Права**: коды в `app/permissions.py`; на каждый запрос вычисляется, в каких юрлицах действует каждое право (`Scope`). Суффикс `_own` — «только своё».
- **Вход**: непрозрачные сеансы на сервере (cookie `erp_session`, HttpOnly, SameSite=Lax), в базе только sha256 токена; защита от подделки запросов через заголовок `X-CSRF-Token`.
- **Защита данных в самой базе** (миграция `0001_initial.py`): триггеры запрещают менять и удалять журнал действий, события обращений, историю статусов, исправления листов; `guard_readings` запрещает менять показания. Частичные уникальные индексы: один открытый лист на машину.
- **Ошибки** возвращаются как `{code, message, field}`; ошибки проверки полей — `{code: "validation", fields}`.
- **Время** хранится в UTC, показывается по часовому поясу организации (`ORG_TIMEZONE`).
- **«Сегодня»** на сервере считается только через `org_today()` из `app/common.py`, а не через `dt.date.today()`: контейнер работает в UTC, и после полуночи по местному времени дата отставала бы на день (например, водитель с «работает с сегодня» оказывался «не в юрлице машины»). В браузере то же делает `todayIso()` из `format.ts`.
- **«Последний день» включается в срок** (`ended_on = сегодня` значит «работает до конца дня»). Поэтому кнопка «Снять» у закрепления водителя без даты ставит последним днём вчера, а закрепление, сделанное и снятое в один день, удаляется (в журнале действий остаётся).
- **Нумерация** листов и обращений — атомарная (`INSERT … ON CONFLICT … RETURNING`), своя для каждого юрлица.

- **Учётные разделы** (справочники и деньги: контрагенты, тарифы, константы, топливные карты, штрафы, аренда, расходы, выплаты, счета, касса): каждый описан один раз в `app/resources.py` (поля, подписи, правила), а общий каркас `app/registry.py` даёт для него список с поиском, отбором по датам и состоянию, итоги, выгрузку в CSV, добавление, правку, архив с причиной, возврат из архива, права `<раздел>.view/create/edit/void`, запись в журнал и проверку связей (техника, сотрудник и счёт должны быть из того же юрлица). Экран один для всех (`frontend/src/pages/Registry.tsx`) и строится по описанию с сервера (`/api/<раздел>/meta`). Новый такой раздел = модель + миграция + права + запись в `resources.py` + строка в `frontend/src/sections.ts`. Тесты: `tests/test_registry.py`.
- **Деньги**: суммы хранятся как `Numeric(14,2)`, принимаются только обычные числа (запятая или точка, пробелы допустимы; «1e3», «inf» и т. п. отклоняются), округление до копеек. Записи не удаляются, а уходят в архив.
- **Сводка и кабинет водителя**: `app/routers/roster.py` (`GET /api/roster`, выгрузка `/api/roster/export.xlsx` (и `.csv`); блоки наряда, рейса, заправки и обращений приходят только если есть право на них) и `app/routers/driver.py` (`GET /api/driver/home`, нужно право `vehicles.view_own`). Главная водителя в `frontend/src/pages/DriverHome.tsx` включается по правам: есть `vehicles.view_own` и нет `vehicles.view`.
- **Работа без связи**: очередь записей в IndexedDB (`frontend/src/outbox.ts`, хранилище `erp-outbox`; записи рейса и заправки, отметки наряда и фото; отправляются по порядку; при ответе сети 5xx или обрыве очередь останавливается и ждёт, при отказе 4xx запись остаётся с причиной), уменьшение фото (`images.ts`), служебный скрипт `frontend/sw-template.js` (в `dist/sw.js` его кладёт плагин в `vite.config.ts`; сохраняет оболочку программы и данные только четырёх запросов водителя; ответы 401 и 403 из сохранённого не подменяются) и `offline.ts` (регистрация, стирание сохранённого при выходе и смене человека). Тарифы получили вид (`Tariff.kind`: `customer`, `work`, `repair`); у сотрудника два назначения: `work_tariff_id`, `repair_tariff_id`. Сумма не хранится, а считается при чтении (`app/services/payroll.py`: `amounts`, `month_pay`, `totals`): за час = часы × ставка, за сутки = ставка один раз на (сотрудник, день, вид), архивные записи дают 0. Проверки ввода собраны в `check_entry` и общие для механика и офиса. Маршруты `app/routers/payroll.py`: `GET /api/payroll/mine` (водитель смотрит свой месяц, вносить нечего), `GET/POST /api/payroll/enter` и `POST /api/payroll/enter/{id}/delete` (страница механика «Внести часы», без денег), `GET /api/payroll/tariffs`, `PUT /api/payroll/employees/{id}/tariffs`; офисный раздел «Часы работы и ремонта» — универсальный справочник `worklog` в `resources.py`. Сайт: `pages/MyTime.tsx` (страница «Мои часы», только просмотр), `pages/HoursEntry.tsx` (страница механика «Внести часы»), `components/EmployeePay.tsx` (блок «Оплата» в карточке сотрудника), `pages/Timesheet.tsx` (табель-деньги). Тесты: `tests/test_worklog.py`, `tests/test_timesheet.py`.
- **Выбор тарифа при внесении часов, отчёт по зарплате, табель-деньги** (миграции `0018`, `0019`). `WorkLog.tariff_manual` (`0018`): тариф выбран вручную, переключение «Работа/Ремонт» (`day-kind`) его не перезаписывает. В форме `worklog` поле `tariff_id` ссылается на `pay_tariff` (`/api/options/pay_tariff`: действующие тарифы с единицей час/сутки, поле `group`); `_wl_prepare` в `resources.py` решает, откуда брать ставку (выбранный тариф → `payroll.snapshot_of`, иначе карточка → `payroll.snapshot`; для офиса без тарифа — ошибка поля `tariff_id`). `POST /api/payroll/preview` считает «эта запись» и «за день» для формы (`payroll.preview_entry`, права `worklog.create|edit`, область юрлица). Отчёт `salary` в `services/reports.py` (`report_salary`). Табель (`routers/timesheet.py`) показывает только деньги и требует `timesheet.view` и `worklog.view`; право `timesheet.edit` и отметки убраны, `0019` удаляет право из `permissions` и `role_permissions` (иначе сохранение ролей на старой базе отклоняло бы устаревшую строку). Сайт: `components/WorklogPreview.tsx`, список тарифов с группами в `pages/Registry.tsx`, `pages/Timesheet.tsx`, `pages/TimesheetPrint.tsx`. Тесты: `tests/test_worklog.py`, `tests/test_timesheet.py`.
- **Загрузить счёт: чтение файла и внесение** (без миграции). `app/services/ocr.py`: tesseract (`rus+eng`, `--psm 6`) и `pdftoppm` через `subprocess` с пределами времени (40 с на шаг, 90 с на запрос, не больше двух чтений одновременно); картинка нормализуется (EXIF-поворот, серый, контраст, ширина около 2000 px), листы пробуются в поворотах 0/90/270/180 до первого «похожего на счёт» результата (`score`). Если программ нет, `available()` ложно и чтение молча выключено. `app/services/bills.py`: `extract_text` (текст PDF; нет текста или он «битый» — страницы как картинки; фото — распознавание), `parse_bill_text` терпим к ошибкам распознавания (знак номера, точка вместо запятой, пробелы в дате, исказившееся «ИНН» и «тел.», «без НДС», `buyer_inn`), `words_match` и `confirm_total` (сумма со скана или фото подтверждается прописью либо повтором суммы вместе с сошедшимся НДС). `POST /api/bills/auto` в `routers/bills.py` (форма: `files`, `note`, `legal_entity_id`; право `bills.create`): юрлицо по выбору человека, иначе по ИНН покупателя, иначе по юрлицу машины, иначе единственное доступное; недостающее или неподтверждённое возвращается как `created: false` с `found`, `missing`, `note`, а сайт открывает форму с этим (`pages/billAuto.ts` передаёт данные и файлы форме); дубль возвращается как `duplicate`. `POST /api/bills/recognize` читает так же, ничего не сохраняя. Сайт: `pages/BillAuto.tsx`, правки `Bills.tsx`, `BillForm.tsx`, `BillCard.tsx`. В `backend/Dockerfile` добавлены `tesseract-ocr tesseract-ocr-rus poppler-utils`.
