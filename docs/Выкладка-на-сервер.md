# Выкладка на сервер за общим Nginx

Для сервера, где уже работают другие сайты и один общий Nginx раздаёт им домены. Программа **не открывает ни одного порта** (ни 80 и 443, ни 8080, ни 5432, ни 3000, ни 5173), поэтому ни с чем на сервере не столкнётся. Путь запроса: пользователь → ваш общий Nginx (https) → контейнер `avtopark-web` → сервер приложения → база.

Файлы для этого:

| Файл | Зачем |
|---|---|
| `docker-compose.server.yml` | запуск программы на сервере; подключается к общей сети `proxy-network` |
| `.env.server.example` | образец настроек для сервера (копируется в `.env`) |
| `deploy/nginx-server-block.conf` | кусок для вашего общего `nginx.conf` |
| `deploy/web-nginx.conf` | внутренний nginx сайта; менять не нужно |

Обычный `docker-compose.yml` (для компьютера и локальной сети) остаётся как был.

## Что нужно заранее

- Docker с docker compose и ваш общий Nginx, который уже работает. Сеть `proxy-network` создана: `docker network ls | grep proxy-network`.
- Домен (например, на duckdns) указывает на сервер. В файлах для примера стоит `avtopark-erp.duckdns.org`; если у вас другой, замените его в `deploy/nginx-server-block.conf` и в `.env` (строка `PUBLIC_URL`).

## Шаги

1. Скопируйте папку проекта на сервер, например в `/opt/avtopark-erp` (`git clone` или WinSCP). Файл `.env` с компьютера копировать не нужно.
2. Создайте настройки: `cd /opt/avtopark-erp && cp .env.server.example .env && nano .env`. Замените `POSTGRES_PASSWORD` и `ADMIN_PASSWORD` на свои (пароль: `openssl rand -hex 24`) и проверьте `PUBLIC_URL`. Остальное можно оставить. Строку `COMPOSE_FILE=...` не удаляйте: из-за неё команды `docker compose ...` берут серверный файл сами.
3. Запустите: `docker compose up -d --build`. Первая сборка занимает 5–10 минут. Проверка: `docker compose ps`, все три службы (`db`, `backend`, `avtopark-web`) должны быть в состоянии «Up», а `backend` и `db` ещё и «healthy».
4. Подключите Nginx (в этом порядке, иначе остановятся все ваши сайты):
   - В `nginx.conf` внутрь `http { ... }` вставьте **ШАГ 1** из `deploy/nginx-server-block.conf`. Проверьте и перечитайте настройки: `nginx -t`, затем `nginx -s reload` (внутри вашего контейнера с Nginx, как для других проектов).
   - Выпустите сертификат так же, как для других доменов. Если у вас используется `/var/www/certbot`, как в вашем конфиге, команда такая: `certbot certonly --webroot -w /var/www/certbot -d avtopark-erp.duckdns.org`.
   - Когда файлы сертификата появились, **замените ШАГ 1 на ШАГ 2**, снова `nginx -t` и `nginx -s reload`.
5. Откройте https://ваш-домен, войдите под `ADMIN_LOGIN` и паролем из `.env` и сразу смените пароль в «Профиле». После этого две строки `ADMIN_*` из `.env` можно удалить.

## Если что-то не так

| Что видно | Что проверить |
|---|---|
| 502 Bad Gateway | `docker compose ps`: запущен ли `avtopark-web`. Подключён ли он к общей сети: `docker network inspect proxy-network` (в списке должен быть `avtopark-web`). |
| Nginx не перечитывает настройки | `nginx -t` покажет строку с ошибкой. Чаще всего вставлен ШАГ 2 до появления сертификата. |
| Вход не запоминается | Открывать нужно по https, и в `.env` должно быть `COOKIE_SECURE=true`. После правки `.env`: `docker compose up -d`. |
| 413 при загрузке сканов | В блоке сайта в Nginx должна быть строка `client_max_body_size 60m;`. |
| Вход блокируется у всех сразу | Программа считает всех одним человеком. Проверьте в блоке Nginx строку `proxy_set_header X-Forwarded-For $remote_addr;`. |
| Занят порт | Здесь этого не бывает: программа порты не открывает. |

## Что где лежит

- Закрытая сеть проекта: `db` и `backend`. Наружу они не видны. Сайт обращается к серверу приложения по имени `avtopark-backend`, чтобы оно не совпало с чужими контейнерами в общей сети.
- Общая сеть `proxy-network`: только `avtopark-web`. Имя для Nginx: `http://avtopark-web:80`.
- Данные в томах Docker: `pgdata` (база) и `backups` (копии). Пересборка (`--build`) данные не стирает.
- Журналы контейнеров ограничены тремя файлами по 10 МБ, диск не заполнят.

**Не выполняйте на сервере `docker compose down -v`**: ключ `-v` удаляет тома, то есть всю базу и копии.

## Обновление и копии

- Обновление: сделайте копию (раздел «Резервные копии» в программе), затем `git pull` и `docker compose up -d --build`. Схема базы обновится сама.
- Копии лежат на том же сервере, поэтому скачивайте их кнопкой «Скачать» или настройте отправку копий в Telegram/на почту (см. [Telegram-и-почта.md](Telegram-и-почта.md)).
- Восстановление: `./scripts/restore.sh файл.dump`, как описано в README. Скрипт сам понимает, что запуск серверный.
- Если вы меняете `frontend/nginx.conf` (заголовки, размер файлов), внесите то же в `deploy/web-nginx.conf`.

## Что проверено, а что нет

Проверено: файл запуска читается (`docker compose config`), в нём нет открытых портов, подключена внешняя сеть `proxy-network`; конфиги Nginx проходят `nginx -t`; на пробном Nginx вся цепочка работает (переход на https, загрузка 30 МБ проходит, 70 МБ отклоняется, адрес клиента нельзя подделать, https доходит до сервера приложения); скрипт восстановления проверен с подставным docker.

Не проверено: реальный запуск Docker на вашем сервере, выпуск сертификата и работа вместе с вашими остальными проектами. Это первый запуск, смотрите `docker compose ps` и `docker compose logs backend`.
