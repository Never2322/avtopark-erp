# Перенос из старой программы

Старая программа (`replica-clone`, SQLite) продолжает работать и не тронута. Разделы перенесены в новую программу; данные из старой базы переносит отдельная команда (см. ниже «Как перенести данные»).

## Как перенести данные

1. Закройте старую программу (или хотя бы ничего в ней не меняйте) и найдите её файл базы, у него расширение `.db`. Файл не меняется: программа читает его копию.
2. Запустите новую программу (`Запустить.bat`) и дважды щёлкните **`Перенести данные из старой программы.bat`**. Файл базы можно перетащить на этот `.bat` или на окно, когда оно спросит путь.
3. Идёт **пробный запуск**: всё переносится, но в конце откатывается. На экране итоги по каждой таблице (прочитано, перенесено, уже было, пропущено), полный отчёт сохраняется в файл `Отчёт о переносе.txt` рядом с `.bat` и открывается в Блокноте.
4. Если отчёт устраивает, ответьте `1`. Перед записью программа сама делает копию новой базы (раздел «Копии»), потом записывает данные.
5. Повторный запуск безопасен: перенесённое помнится в таблице `legacy_ids`, второй раз не задваивается. Так можно донести записи, добавленные в старую программу позже.

То же без `.bat` (из папки проекта): `docker compose exec backend python -m app.cli import-old --db /tmp/old.db [--apply] [--default-entity "ООО Север"] [--report /tmp/otchet.txt]`. Без `--apply` данные не записываются.

### Что и как переносится

| Старая таблица | Куда | Как |
|---|---|---|
| `organizations` | юрлица | к названию добавляется форма (ООО, ИП), если её там нет |
| `employees` | сотрудники | юрлицо из организации сотрудника |
| `vehicles` | техника | юрлицо из организации машины; машина с таким же госномером, уже заведённая в новой программе, **не дублируется**, а связывается; пустой номер допускается |
| показания, журнал статусов | показания, история статусов | уменьшение пробега переносится как «на проверку» с пометкой «подозрительное» и **не** считается текущим пробегом; для машин с моточасами нулевой пробег пропускается |
| ТО, мероприятия, шины, ремонты, финансы по технике | вкладки карточки машины | |
| страховки | документы техники | ОСАГО, КАСКО, другое; без контроля срока попадают в архив |
| контрагенты, тарифы, константы, нормы СИЗ, каталог деталей | справочники | |
| топливные карты, заправки, штрафы, аренда, прочие расходы | разделы «Техника» и «Деньги» | |
| касса, заказы, документы | касса, заказы, документы | суммы из копеек в рубли; номера сохраняются, при совпадении выдаётся ближайший свободный, старый номер пишется в примечание |
| склад | склады, товары, движения | |
| выплаты, СИЗ, события сотрудников, табель, календарь | разделы сотрудников | |
| рейсы, наряды, путевые листы | записи водителей, наряды, путевые листы | путевой лист без водителя пропускается; из «выданных» открытым остаётся только последний по машине и только если срок не вышел, остальные закрываются |
| обращения, комментарии, детали, счета на ремонт | обращения, события, детали, счета | приоритет: срочный → высокий, «машина стоит» → срочный; статусы: новое и в работе → «в работе», детали → «ждёт деталей», выполнено, отклонено → «отменено» |

Время из старой базы читается как местное (`Asia/Novosibirsk`, как `ORG_TIMEZONE`) и сохраняется в UTC; служебные времена создания записей считаются UTC.

### Что НЕ переносится

- **Пользователи и пароли.** Пароли в старой программе устроены иначе. Логины, имена и роли выводятся в отчёте, пользователей нужно завести заново в разделе «Пользователи».
- **Файлы и фото** (счета, чеки, накладные, фото нарядов и обращений): в старой базе хранятся только имена файлов на диске. Загрузите нужные заново.
- Журнал действий, старые уведомления, очереди Telegram и push, правила почты, объявления и ответы, шаблоны путевых листов, настройки.
- Зарплаты сотрудников (в новой программе этого поля нет).

### Что надо знать

- Запись, которую база отвергла (неверная дата, число не по размеру и т. п.), **пропускается** и попадает в отчёт, остальные переносятся дальше. Просмотрите раздел «Предупреждения» в отчёте.
- Если у машины или сотрудника нет организации, он попадает в юрлицо по умолчанию: ключ `--default-entity`, иначе первая организация, иначе «Основная организация».
- Проверено на **выдуманной** старой базе (20 тестов: две организации, одинаковые номера в разных написаниях, уменьшение пробега, путевой лист без водителя, повторные запуски, файл не той программы). Настоящая база не видна, поэтому на ней возможны записи, которые не перенесутся; отчёт покажет какие.
- После переноса сверьте несколько цифр со старой программой (остатки на складе и в кассе, итоги за месяц): отчёты новой программы считаются по-своему.
